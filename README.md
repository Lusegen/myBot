# Telegram-бот для частной врачебной практики

Бот, который ведёт приём вместо администратора: пациент сам записывается на
консультацию, может вызвать врача на дом или переписываться с врачом в чате
Telegram. Расписанием, услугами и текстами сообщений врач управляет прямо в
боте — с телефона, без сайта и отдельной админки.

## Возможности

**Для пациента**
- Запись на приём: выбор даты и свободного времени (сетка слотов строится автоматически)
- Вызов врача на дом: имя, телефон, описание жалоб
- Консультация в чате: переписка с врачом в течение 24 часов с момента активации
- Список своих записей

**Для врача (админ-панель внутри бота)**
- Все записи пациентов и заявки на вызов на дом
- Настройка сетки слотов: начало и конец приёма, шаг
- Блокировка дней — отпуск, праздники, выходные
- Включение и отключение услуг, управление видимостью кнопок
- Редактирование текстов: приветствие, ссылка на консультацию, сообщение для вызова врача
- Переписка с пациентами: активные чаты, история, режим непрерывного чата с авто-выходом через 20 минут
- Пользовательская панель — посмотреть бота глазами пациента

## Стек

- Python 3.13, asyncio
- aiogram 3.22 (long polling)
- SQLite через стандартный модуль `sqlite3`, две базы
- python-dotenv для конфигурации

## Структура

```
main.py                            точка входа: инициализация БД, хендлеры, polling

handlers/
  start.py                         /start и главное меню
  record.py                        запись на приём
  consultation.py                  вызов врача на дом, запись на консультацию
  paid_consultation_handlers.py    консультация в чате, окно 24 часа
  admin_core.py                    админ-панель: записи и заявки
  admin_slots_settings.py          настройка сетки слотов
  admin_block_dates.py             блокировка дней
  admin_settings.py                включение услуг и видимость кнопок
  settings_handlers.py             редактирование текстов
  admins/chat_manager.py           переписка врач ↔ пациент
keyboards/                         клавиатуры
database/                          схема, запросы, планировщик, очистка
utils/                             генерация слотов, работа с датами, валидация

```

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env           # вписать BOT_TOKEN и ADMIN_ID
python main.py
```

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ADMIN_ID` | да | telegram_id врача: админ-панель и уведомления о записях |
| `DB_NAME` | нет | файл БД с расписанием, по умолчанию `bot_schedule.db` |
| `SETTINGS_DB_NAME` | нет | файл БД с настройками, по умолчанию `bot_database.db` |
| `CONSULTATION_SESSION_DURATION` | нет | длительность консультации в часах, по умолчанию 24 |

## Базы данных

Файлы `bot_schedule.db` и `bot_database.db` в репозиторий не входят: они
создаются автоматически при первом запуске (`CREATE TABLE IF NOT EXISTS` в
`database/db_init.py`, `database/settings_db.py`, `database/blocked_dates.py`).

| Файл | Таблица | Назначение |
|---|---|---|
| `bot_schedule.db` | `users` | пациенты и врач (`is_doctor`) |
| | `schedule` | слоты: дата, время, `свободно` / `занято`, кто записан |
| | `home_visits` | заявки на вызов врача на дом |
| | `blocked_dates` | заблокированные дни |
| | `button_settings` | видимость кнопок в меню |
| | `consultation_sessions` | активные консультации и время их окончания |
| | `chat_messages` | переписка врач ↔ пациент |
| `bot_database.db` | `bot_settings` | тексты и настройки слотов из админ-панели |

## Как работает расписание

Слоты генерируются на 30 рабочих дней вперёд с шагом из настроек; выходные и
заблокированные дни пропускаются. Раз в сутки планировщик добавляет новые дни и
удаляет устаревшие **свободные** слоты — подтверждённые записи сохраняются и
остаются в базе как история приёмов.

## Режим чата

Переписка с пациентом идёт прямо в Telegram, без отдельного веб-интерфейса.

- «💬 Активные чаты» — открытые консультации с метками новизны (🆕 первый час, ⏳ первые три часа), именем пациента, телефоном и остатком времени; при открытии списка сессии старше 72 часов вычищаются.
- «Ответить» включает **режим непрерывного чата**: пока он активен, любое текстовое сообщение врача уходит пациенту, сохраняется в `chat_messages` (`sender_type = 'doctor'`) и подтверждается отчётом «✅ Отправлено … ⚡ Режим чата активен».
- Выход — кнопкой «⬅️ Назад к списку» или автоматически после 20 минут неактивности: фоновая задача проверяет раз в минуту и присылает врачу уведомление.
- История переписки открывается отдельной кнопкой — последние 50 сообщений с подписями «👨‍⚕️ Врач» / «👤 Пациент».
- Пациент пишет в обычный диалог с ботом: сообщение сохраняется и пересылается врачу с шапкой — имя, номер сессии, телефон и сколько часов осталось до конца консультации.
- Если пациент заблокировал бота, врач получает сообщение о недоставке, а режим чата сохраняется — можно ответить другому пациенту.

## Известные ограничения

- даты хранятся строкой формата «9 июн», без года: сравнение идёт по строке, поэтому на стыке годов возможны неточности;
- SQLite вызывается синхронно из async-хендлеров — рассчитано на нагрузку частной практики, не на поток;
- текст, пришедший от пациента, пересылается врачу с `parse_mode="HTML"` без экранирования: сообщение с символами `<` или `>` может не дойти.
